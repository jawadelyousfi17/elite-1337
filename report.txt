WHAT WAS ADDED OR CHANGED

1. Ranking data and eligibility
   - Separated Piscine year/month from Common Core entry cohort. The cohort uses
     the UTC year of the Common Core cursus_users.begin_at value; missing dates
     display as Unknown.
   - Added verified 1337 campus coverage: Khouribga (16), Benguerir (21),
     Tétouan (55), and Rabat (75).
   - Added a central classification layer to exclude API-marked staff,
     nonstudents, inactive accounts, alumni, ended enrollments, and optional
     explicitly listed user IDs from competitive rankings. Authentication
     remains separate from ranking eligibility.
   - Kept global ranking deduplicated across campus memberships. Selected
     populations recalculate competition ranks before search and pagination.
     Students at equal levels share a rank.
   - Did not treat blackholed_at alone as proof of a current status: live active
     records often contain a future deadline in that field.

2. Leaderboard and profiles
   - Redesigned /leaderboard with campus, Common Core cohort, Piscine year,
     Piscine month, and login filters; two-decimal level display; responsive
     desktop and mobile layouts; and dataset freshness information.
   - Defaulted the leaderboard to the signed-in student's primary campus and
     Common Core cohort. The last selected cohort is saved per user in browser
     localStorage.
   - Updated /me and student profiles to use the same cohort rank calculation
     and show Common Core and Piscine information separately.
   - Added 42 profile images where the browser can load them, with an initials
     fallback when an image fails.
   - Kept separate on-site and 42 Intra profile links. External Intra links
     open in a new browser tab.

3. Piscine Explorer
   - Added /piscines and navigation to it. It filters candidates by campus,
     Piscine year/month, login, and admission outcome.
   - Added bounded, complete API pagination and a one-hour cache for Piscine
     lists. Staff and nonstudent accounts are filtered from the explorer.
   - Shows Accepted only when a Common Core enrollment verifies it. Other
     outcomes stay Unknown; absence of a Common Core record is not treated as
     rejection.

4. Activity, reliability, and documentation
   - Kept the existing UTC workstation-session calculation: Monday–Sunday
     weeks and monthly cycles from the 28th through the 27th. The UI now labels
     the result as workstation session time rather than official Intra logtime.
   - Added a loading state, updated API schemas, documented optional excluded
     user IDs, and updated README deployment and API-limit notes.
   - Added or updated regression tests for cohort classification, campus scope,
     eligibility, rank ties, Piscine filters, admission uncertainty, complete
     pagination, OAuth, and logtime boundaries/overlap.

CURRENT LIMITS

     Not accepted outcome. That filter therefore has no inferred results.
   - Piscine level is omitted until it can be fetched reliably within the API
     request budget.
   - Some 42 image URLs may return HTTP 403 in a browser; initials remain the
     fallback.

     and persistent snapshots would be needed for stronger traffic guarantees.

     student profiles is still the final user-facing check.

V3 ADDITION — CLUSTER EXPLORER

   - Added protected /clusters navigation and a four-campus explorer for
     Khouribga, Benguerir, Tétouan, and Rabat. A verified 1337 campus
     membership is required; a member can switch among the four campuses.
   - Added a privacy-filtered /api/clusters endpoint. It returns workstation
     IDs, anonymous states, counts, completeness, and snapshot freshness.
     It does not return user IDs, logins, avatars, raw location records, or
     individual session timestamps.
   - Verified the 42 campus-location endpoint and active-location filter
     against all four campuses. Active pages are checked for total count,
     uniqueness, and campus consistency. Recent location records supply a
     bounded sample of observed workstation names, not a seat inventory.
   - Added campus-specific workstation parsing and discovered groups from
     live hosts: Khouribga e1/e2/e3; Benguerir e1/c3/c4; Tétouan c1/c2;
     Rabat c1/c2. These are observed groups, not a claim that no others exist.
   - Added Occupied, Available, and Unknown classification. Duplicate
     sessions for one user are merged; conflicting users, stale, ended,
     malformed, or partial data cannot certify an empty seat. Disabled
     workstations are excluded from available counts.
   - Added workstation search, Find Empty Seats, occupancy summaries, seat
     details, responsive directory views, a future-ready floor-plan renderer,
     and 60-second visible-page refresh with a manual button.
   - Added an empty version-controlled layout registry for verified physical
     coordinates and enabled-seat inventory. The supplied screenshots are
     design references only. No authoritative Khouribga layout or inventory
     was available, so the current interface clearly labels its directory
     fallback and certifies zero empty seats.
   - Anonymous active-host snapshots cache for 180 seconds. The bounded
     observed-host sample caches for one day. The interface shows the
     actual update time and treats snapshots older than four minutes as
     Unknown.

AVATAR ACCESS INVESTIGATION (2026-10-19)

   - GET /v2/users/yikoubaz with a 42 application OAuth token returned JSON
     image.link and image.versions URLs on cdn.intra.42.fr. It did not return
     image bytes. No documented 42 user-image byte endpoint was found.
   - The same CDN URL returned HTTP 403 without an Intra browser session.
     One bearer-token request returned JPEG bytes, but repeated bearer-token
     requests from Python and Node returned HTTP 403. A local Next.js image
     route using the bearer token also returned no image. Bearer access is
     therefore not reliable enough to deploy as an avatar proxy.
   - The attempted proxy was removed before deployment. Existing pages still
     show an image when the browser can access its 42 URL and otherwise use
     the shared Avatar component's initials fallback. No Intra cookies were
     copied or used, and no third-party image storage was added.
   - No production change was deployed for this investigation. A browser
     authenticated only to 1337 Ranks remains subject to the CDN's 403, so
     cookie-independent avatar display is not currently verified.

V3.1 — PERSISTENT STUDENT AVATARS (LOCAL IMPLEMENTATION)

   - Added a private Supabase Storage design with an SQL setup file for the
     student-avatars bucket and student_avatars user-ID mapping table.
     The Supabase service-role key is used only in server code.

   - Added avatar management on /me and switched the leaderboard, student
     profiles, dashboard, and Piscine Explorer to uploaded avatars with an
     initials fallback. Cluster Explorer remains anonymous.
   - 40 automated tests passed. TypeScript checking and the production build
     passed. Tests cover validation, owner checks, private reads, batch
     lookup, replacement, deletion, missing objects, and storage errors.
   - The built app returned 401 for anonymous avatar reads and uploads, 403
     for a cross-origin delete, 404 for an invalid signed image reference,
     and 503 for a signed upload while Supabase was unconfigured.
